## 1. 拿到数据

- 文件：`SHEVDC_OV6N7709.csv`，约 640 KB，UTF-8，无表头说明。
- 第一眼：24 列，时间列 + 车辆状态 + 电压电流 + SOC + 单体电压/温度，**典型的 GB/T 32960 格式**，但不知道字段口径。
- 第一件事不是画图，而是**确认字段含义**：`vehiclestatus` / `chargestatus` 的 1/2/3/4 分别代表什么？查 GB/T 32960 后才确定：
  - `vehiclestatus`：1=启动，2=熄火
  - `chargestatus`：1=停车充电，2=行驶充电（能量回收），3=未充电，4=充电完成

## 2. 探查阶段发现的四个问题

| 现象 | 影响 | 处理 |
|------|------|------|
| 6,231 行只覆盖 35 小时里的一半时间（覆盖率 49.3%） | 直接按 10 秒一条补全会凭空造出数据 | 不补全，改为"缺口分析"作为一个发现 |
| 106 段 >60 秒的缺口，最长 13.5 小时 | 能耗直接积分会把缺口时间当用电，虚高几十倍 | 积分前过滤 `dt ≤ 30s` |
| `summileage` 有 **4,263 行是字符串 `"ffill"`**（占 68.4%，上游导出脚本把 `fillna` 的方法名写进了数据） | 该列无法直接当数值算里程 | `pd.to_numeric(..., errors="coerce")` 转成缺失后取有效值算增量（这些段是里程停滞的平段，不影响 min/max）；正式清洗应前向填充，详见 WorkBuddy 记录 |
| `insulationresistance` 数值 4437–6872，单位口径不明 | 无法判断是否合规 | **不解读**，只在数据说明里标注 |

> 这一步的教训：**先确认字段和单位，再谈分析**。字段口径错了，后面所有结论都是错的。

## 3. 分析设计的三个决定

**决定 1：用状态字段切分工况，不用速度阈值。**
`vehiclestatus` + `chargestatus` 是上报的原始状态，交叉后自然得到四类工况（停车充电 / 行驶 / 能量回收 / 充电完成）。若用"speed > 0 就是行驶"，无法区分充电和怠速，也会把能量回收算成普通行驶。

**决定 2：能量积分必须过滤长缺口。**
公式本身很简单：`能量 = Σ(电压 × 电流 × Δt)`。但 Δt 里有 13 小时的缺口，不过滤就会把"车没上传数据"当成"一直在放电"。最终只在 `0 < Δt ≤ 30s` 的行上积分。

**决定 3：电池一致性看"极差"，不看容量。**
单次 1.5 天的数据无法测容量衰减，能直接观测的是一致性：`max_cell_volt - min_cell_volt`、`max_temp - min_temp`。这是数据能支撑的结论边界。

## 4. 过程中遇到的问题（踩坑记录）

1. **pandas 3.0 的 `boxplot(by=Series)` 报错**：`ValueError: The truth value of a Series is ambiguous`。
   解决：先 `df.assign(soc_bin=...)` 再 `boxplot(by="soc_bin")`，用列名而不是 Series。
2. **SOC 曲线出现"长时间水平线"**：一开始以为是异常，其实是**数据缺口**（车没上线），折线把两端连起来了。后来在时间线上用阴影标出充电时段，才看清结构。
3. **两次充电的 SOC 起点差别很大（7% 和 62%）**：第一版文案写成"每次充电前电量都很低"，核对后发现第二次并不低，改为"两次都在电量较低时开始"。**结论必须回到数据核对**。

## 5. 最终产出

- 4 类工况占比：停车充电 70.1%、行驶 24.7%、能量回收 4.4%、充电完成 0.9%
- 行驶 3.73 小时 / 214 km，百公里电耗 21.5 kWh/100km
- 2 次慢充：3.25 kW，共充入 37.58 kWh，SOC 7%→96% / 62%→84%
- 电池：单体电压极差中位数 9 mV（p95 17 mV），温度 5–13 °C、温差 ≤2 °C
- 4 张图：工况占比、SOC×车速时间线、充电曲线、电压一致性

## 6. 如果继续做

- 多车数据 → 车队级对比（能耗分布、充电习惯聚类）
- 快充数据 → 验证恒流恒压特征，对比慢充效率
- 长周期满充满放 → 反推电池可用容量与衰减趋势
- 把"缺口"本身做成指标：上线率、数据丢包率，用于评估终端质量
